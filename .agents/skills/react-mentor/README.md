# React Mentor

React を **実装しながら学ぶ** ための Codex CLI 用 Skill です。  
Codex が最初から最後まで全部実装するのではなく、学習者が取り組むべき部分を切り出し、実装後にレビューしながら段階的に進めます。

この Skill は、React の学習順序を考慮しつつ、**今の学習段階に合った課題を出すこと** を目的にしています。  
また、学習のために不自然な実装を強制しないように、必要であれば例外的に高度な概念を Codex 側が補助的に扱うよう設計しています。

## この Skill でできること

- React コンポーネントの実装を Codex と一緒に進める
- 学習者に 15〜30 分程度の実装課題を切り出す
- 実装完了後にコードレビューを行う
- 学習履歴を `.codex-learning/progress.json` に保存する
- 学習済みテーマや現在の段階を踏まえて次の課題を調整する
- `props` より前に `context` を主課題にしない、のような学習順序を守る
- ただし実装を不自然にする場合は、必要な高度機能を例外的に許可する

## 対象

- React 学習者
- Codex CLI を使って、実装しながら React を身につけたい人
- 既存の React プロジェクト上で、小さく課題を切りながら学びたい人

## 前提

- この Skill は **React 専用** です
- Next.js は対象外です
- TypeScript を優先しますが、既存プロジェクトが JavaScript の場合はその構成に従います
- 学習履歴は `.codex-learning/progress.json` に保存されます


## 初回開始時の確認

この Skill は、セッション開始時にいきなり課題を出すのではなく、まず今回の進め方を確認します。

最初に次の項目を確認します。

- **review intensity**  
  レビューの厳しさ。`light / normal / strict` から選びます。

- **task size**  
  1 回の課題の大きさ。`small / medium / large` から選びます。  
  何分くらいの粒度で進めたいかに対応しており、学習を小さく刻みたいか、ある程度まとまった単位で進めたいかをここで決めます。

ユーザーが明示しない場合は、Skill 側でデフォルト値を使って開始します。  
基本は **review intensity = normal**、**task size = medium** を前提に進めます。

## 使い方

Codex CLI 上で、React プロジェクトのルートにこの Skill を配置したうえで、次のように依頼してください。

### 基本例

```text
この React コンポーネントを一緒に実装して
````

この依頼をすると、Skill は最初に今回の進め方を確認します。
その後、学習履歴ファイル `.codex-learning/progress.json` を読み取り、現在の学習段階に合う形で課題を切り出します。

### 最初から粒度を指定して始める例

```text
この React コンポーネントを一緒に実装して。
review intensity は strict、
task size は medium で進めて
```

このように最初から指定すると、確認を短くしてその設定で開始できます。


## セッションの流れ

この Skill は、基本的に次の流れで動作します。

1. `.codex-learning/progress.json` を読み取る
2. 現在の学習段階を確認する
3. 今回の課題に対して、自然な実装方針を決める
4. その中から学習者が担当する部分を切り出す
5. 学習者が実装する
6. Codex がレビューする
7. 学習履歴を更新する
8. 必要なら次の課題を提案する

## 学習履歴について

この Skill は、`.codex-learning/progress.json` を自動で使用します。  
ユーザーが毎回明示的に指定する必要はありません。

- ファイルが存在する場合: 読み込んで現在の学習段階を判断します
- ファイルが存在しない場合: 初回実行として新規作成します
- セッション終了後: 学習内容に応じて更新します

## 学習順序について

この Skill では、React の学習順序を意識して課題を出します。
たとえば、`props` より前に `context` を主課題として出すことは避けます。

想定している基本順序は次の通りです。

1. jsx-and-components
2. props
3. state
4. event-handling
5. conditional-rendering
6. list-rendering
7. lifting-state-up
8. form-handling
9. derived-values-and-simple-effects
10. custom-hooks
11. context
12. performance-basics

ただし、実際の実装を不自然にする場合は、この順序を機械的に優先しません。
**実装の自然さと正しさを優先し、そのうえで学習課題として最適な範囲を切り出す** 方針です。

## 不自然な実装を避けるための方針

学習のために、常に高度な機能を禁止するわけではありません。
たとえば本来 `context` や `custom hook` を使った方が自然なケースでは、それらを完全に封じると設計が不自然になることがあります。

そのためこの Skill では、次のように判断します。

* 今の学習範囲だけで自然に実装できるなら、その範囲で課題化する
* 高度な概念が必要だが学習の主題ではないなら、その部分は Codex が補助する
* 高度な概念を避けると実装品質が下がるなら、無理に禁止しない
* 必要なら例外的に解禁し、その理由をレビューで明示する

## レビューについて

レビューでは、単に動いているかどうかだけでなく、**今回の学習目標に合っているか** も確認します。

基本的に次の観点でレビューします。

* status
* what is working
* issues to fix
* next step

必要に応じて、次に学ぶべきテーマや、まだ使わない方がよい概念も案内します。

## 学習履歴ファイル

学習履歴は `.codex-learning/progress.json` に保存されます。
この Skill では、`progress.json` の形式は固定です。
初回実行時にファイルが存在しなければ作成し、既存ファイルがあって形式が異なる場合は、読み取れる値を使って正規化して書き戻します。

この仕組みにより、次回以降は次のような情報を踏まえて課題を調整できます。

* 学習済みのテーマ
* 現在進行中のテーマ
* 直近で取り組んだ課題
* レビュー強度
* 課題サイズ

## 向いている使い方

* React の基礎を順番に身につけたい
* ただ読むだけでなく、手を動かして学びたい
* 一部は自分で書き、一部は Codex に補助してほしい
* 過去に学んだ内容を踏まえて次の課題を出してほしい

## 向いていない使い方

* React を学ばず、最短で全部自動実装してほしいケース
* 学習順序よりも、常に最適実装のみを優先したいケース

## 例

### 例1: props を学びたい

```text
この React コンポーネントを一緒に実装して。
今の段階に合うように進めて
```

### 例2: 厳しめにレビューしてほしい

```text
この React コンポーネントを一緒に実装して。
review intensity は strict で
```

### 例3: 小さめの課題で進めたい

```text
この React コンポーネントを一緒に実装して。
task size は small で進めて
```

## まとめ

React Mentor は、React の実装を Codex と一緒に進めながら、
**学習順序・実装の自然さ・学習履歴** をバランスよく扱うための Skill です。

ただコードを出すだけではなく、

* 今どの段階か
* 今回どこを自分で書くべきか
* 次に何を学ぶべきか

を整理しながら進めたいときに向いています。
