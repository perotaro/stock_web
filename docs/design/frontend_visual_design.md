# Guppy フロントエンドビジュアル設計

## 1. 文書目的
本書は、Guppy Webシステムにおけるフロントエンドのビジュアル設計を定義する。  
初期段階では公開トップページ `/` を対象とし、表示情報、レイアウト、見た目のトーン、コンポーネントの使い方、実装時の判断基準を明確化することを目的とする。

本書はフロントエンド基本設計を補完する文書であり、見た目を過度に作り込むことではなく、情報の優先順位が明確で、実装しやすく、保守しやすい UI を定義することを重視する。

## 3. スコープ

### 3.1 対象
- 公開トップページ `/` の視覚設計
- API 返却項目と表示内容の対応
- トップページのセクション構成
- 色、文字、余白、カード、ボタンなどの基本ルール
- モバイルおよびデスクトップのレイアウト方針

### 3.2 対象外
- `/login` `/app` `/app/systems/:system_code` `/app/watchlist` の詳細ビジュアル設計
- アニメーションの詳細設計
- Figma などのデザインツール上の作業手順
- 実装時の CSS クラス名やコンポーネント props の詳細定義

## 4. 前提
- 対象画面は公開トップページ `/` とする。
- 公開トップで利用する API は `GET /api/v1/public/summary` とする。
- 表示してよい情報は匿名集計値に限定する。
- 公開トップでは GitHub への外部リンクを置かない。
- 公開トップでは個別銘柄、戦略詳細、当日シグナル生データを表示しない。
- トップページの第一目的は、サービス概要と公開可能な運用状況を短時間で理解できることとする。
- 第二目的は、認証後画面へのログイン導線を自然に提供することとする。

## 5. API 項目と表示対応

### 5.1 取得項目
公開トップページでは、以下の項目のみを表示対象とする。

| API 項目 | 画面表示名 | 表示ルール |
|---|---|---|
| `operating_days` | 当月稼働日数 | `xx日` 形式で表示する |
| `batch_runs_total` | 総実行回数（累計） | 3桁区切りの整数で表示する |
| `success_rate` | 当月成功率 | `%` 表記で表示する |
| `avg_duration_sec` | 当月平均処理時間 | `xx.x 秒` を基本とする |
| `updated_at` | 最終更新日時 | `JST` 表示に統一する |

### 5.2 表示禁止項目
以下は公開トップページで表示しない。

- システム数
- 監視対象件数
- 個別銘柄情報
- 戦略ロジック
- 当日シグナルの生データ
- 運用者向け内部情報

## 6. デザイン方針

### 6.1 トーン
- 方向性は「静かな運用ダッシュボード」とする。
- 派手さよりも、更新されていること、整理されていること、業務アプリとしての信頼感を優先する。
- ポートフォリオ用途を意識しつつも、過度な演出や抽象的なヒーロー表現は採用しない。

### 6.2 避ける表現
- ページ全体をカードだらけにする構成
- 紫や青の強いグラデーションに依存した generic な見た目
- 中身より装飾が目立つヒーロー表現
- 意味の薄い英語キャッチコピー
- API で取得していない指標を雰囲気で追加すること

### 6.3 見せ方の原則
- 画面全体に強弱を作るため、カード化するのは匿名集計セクションに限定する。
- ヒーロー、補足説明、ログイン導線はテキスト主体で構成する。
- 数字は大きく、説明文は短くする。
- セクション数は増やしすぎず、1画面で読める情報量に収める。

## 7. 情報構造

### 7.1 セクション構成
公開トップページ `/` は以下の 5 セクションで構成する。

1. ヘッダ
2. ヒーロー
3. 匿名集計サマリ
4. 公開範囲の説明
5. ログイン導線

### 7.2 セクションごとの役割
| セクション | 主な役割 | 主な内容 |
|---|---|---|
| ヘッダ | サービス名と最小限の導線を示す | ロゴ相当のサービス名、ログイン |
| ヒーロー | サービス概要と更新されている印象を伝える | 見出し、説明文、最終更新日時 |
| 匿名集計サマリ | 公開可能な実績サマリを見せる | 4つの匿名集計カード |
| 公開範囲の説明 | 何を公開しているかを明確にする | 匿名集計のみであることの説明 |
| ログイン導線 | 認証後画面への遷移を促す | CTA 文言、ログインボタン |

## 8. レイアウト設計

### 8.1 デスクトップレイアウト
- ヘッダは横一列とし、左にサービス名、右にログイン導線を置く。
- ヒーローは 2 列に分けず、テキスト主体の 1 カラムとする。
- `最終更新日時` はヒーロー直下の補助情報として配置する。
- 匿名集計カードは `2 x 2` の 4 枚構成とする。
- 公開範囲の説明は、カードではなく区切り線と余白で分ける。
- 下部 CTA は横長の導線領域とし、主ボタンを 1 つだけ置く。

### 8.2 モバイルレイアウト
- すべて 1 カラムで積み上げる。
- ヘッダの導線は `ログイン` のみとする。
- 匿名集計カードは 4 枚を縦積みにする。
- テキスト量はデスクトップよりもさらに短く保つ。
- CTA は画面幅いっぱいに近いボタンとし、押しやすさを優先する。

### 8.3 ワイヤーフレーム
```text
------------------------------------------------
Guppy                                     ログイン
------------------------------------------------

日次更新のシグナルを、公開サマリと認証後画面で確認できる。

公開領域では匿名集計と更新状況のみを表示します。
詳細な判定結果や対象一覧はログイン後に確認できます。

最終更新日時: 2026-04-10 09:00 JST

[ ログインして詳細を見る ]

------------------------------------------------
[ 当月稼働日数 ] [ 総実行回数（累計） ]
[ 当月成功率   ] [ 当月平均処理時間   ]
------------------------------------------------

公開領域で表示する内容
表示内容は匿名集計に限定しており、個別銘柄、戦略詳細、
当日シグナル生データは公開しません。

------------------------------------------------
詳細な結果や対象一覧は、ログイン後画面で確認できます。
[ ログインして詳細を見る ]
------------------------------------------------
```

## 9. ビジュアルルール

### 9.1 カラー
```text
background      #F4F7F8
surface         #FFFFFF
text            #172033
muted           #627086
border          #D8E0E7
accent          #0F766E
accent-strong   #115E59
success         #15803D
```

- 背景は淡い無彩色を基調とする。
- アクセント色は `accent` のみを主に使い、ボタンやリンクの強調に限定する。
- 成功色はステータス補助表示にのみ使い、ページ全体の主役にはしない。

### 9.2 タイポグラフィ
- フォントは `Noto Sans JP` を第一候補とし、導入しない場合は可読性の高い sans-serif 系を用いる。
- サイズは以下の 5 段階を基本とする。
  - ページ見出し: `32px`
  - セクション見出し: `24px`
  - カード値: `28px`
  - 本文: `14px`
  - 補助文字: `12px`
- 数字は本文より大きくし、情報の優先順位を視覚的に示す。

### 9.3 余白
- 余白スケールは `8 / 12 / 16 / 24 / 32` を基本とする。
- セクション間は `32px` 以上あける。
- カード内余白は `16px` から `20px` を基本とする。

### 9.4 境界と装飾
- カードの角丸は `12px` とする。
- 枠線は `border` 色で 1px とする。
- 影は薄い 1 種類のみ使い、強いドロップシャドウは使わない。
- グラデーション背景や装飾イラストは使わない。

## 10. コンポーネント設計

### 10.1 Header
- 左に `Guppy`
- 右に `ログイン`
- 高さは抑えめにし、情報量を増やさない

### 10.2 Hero
- 大きな見出し
- 2 行以内の説明文
- `updated_at` を使った最終更新日時表示
- 主 CTA 1 つ

### 10.3 MetricCard
- 匿名集計サマリ専用
- 要素は `見出し / 値 / 補助説明` の 3 段に限定する
- 補助説明が不要な場合は 2 段でもよい

### 10.4 DisclosureSection
- 公開範囲の説明用テキストブロック
- カード化せず、本文と区切り線で構成する

### 10.5 CTASection
- 画面下部の再導線用
- ボタンは主 CTA のみ
- 文言は「詳細はログイン後画面で確認できる」に統一する

## 11. 表示文言案

### 11.1 見出し
`日次更新のシグナルを、公開サマリと認証後画面で確認できる。`

### 11.2 説明文
`公開領域では匿名集計と更新状況のみを表示します。詳細な判定結果や対象一覧はログイン後に確認できます。`

### 11.3 公開範囲の説明
`表示内容は匿名集計に限定しており、個別銘柄、戦略詳細、当日シグナル生データは公開しません。`

### 11.4 CTA
- 主ボタン: `ログインして詳細を見る`
- 下部導線文: `詳細な結果や対象一覧は、ログイン後画面で確認できます。`

## 12. 状態表示設計

### 12.1 ローディング
- ヒーロー直下または匿名集計セクション上部に簡潔なローディング表示を置く。
- スケルトンを使う場合は、4 枚の匿名集計カード部分だけに限定する。

### 12.2 エラー
- 公開トップの上部または匿名集計セクション直前にエラーメッセージを表示する。
- 文言は簡潔にし、`再試行` ボタンを併設する。
- API の内部情報や詳細エラー文字列は表示しない。

### 12.3 データ欠損
- 項目単位の欠損は `--` 表示を基本とする。
- ページ全体を空白状態にせず、最低限の説明文と導線を残す。

## 13. 実装時の注意
- `/` では API 項目にないメトリクスを見た目の都合で追加しない。
- ヒーロー、公開範囲説明、下部 CTA はカード化しない。
- 数字の単位を UI 側で必ず明示する。
- `updated_at` は `JST` 表示に統一する。
- モバイル表示でカードの横並びを維持しようとせず、素直に 1 カラムへ落とす。
- 実装時のスタイルは、この文書のルールを超えて過度に装飾しない。

## 14. 今後拡張時の扱い
- 将来、公開トップ API に返却項目が追加された場合でも、セクション構成を崩さず匿名集計セクションの中で吸収することを基本とする。
- 追加項目が数値以外の場合は、安易にカード化せず、本文セクションまたは別導線の追加で解決できるかを先に検討する。
- ログイン後画面のビジュアル設計は、本書とは別節または別文書で追加する。
